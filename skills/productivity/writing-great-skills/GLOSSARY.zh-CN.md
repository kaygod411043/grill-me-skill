# 术语表：构建优秀技能

这是关于优秀技能构成方式的领域模型。技能的存在，是为了从随机系统中约束出确定性；根本品质是**可预测性**，下文每个术语都是作用于它的杠杆。本文是 [`writing-great-skills`](SKILL.zh-CN.md) 所披露的参考资料。

术语按轴分组：**调用机制**（如何抵达技能）、**信息层级**（如何组织内容）、**引导**（如何塑造代理运行时行为）和**精简**（如何保持简洁）。每种**失败模式**都放在能够修复它的杠杆旁，并标记为*失败模式*。

任何定义中的**粗体术语**也在本术语表中有定义，可通过标题查找。

## 可预测性

技能使代理每次运行都以相同*方式*行动的程度，即过程相同，而不是输出相同；头脑风暴技能应当以*可预测的方式*产生分歧，其 token 会变化，但行为不会。它是其他所有术语共同服务的根本品质，成本和可维护性只是其表现，而非竞争目标。

_避免使用_：一致性、可靠性、稳健性、输出确定性

## 调用机制

如何抵达技能，以及为这项选择承担的两种负载。

### 模型调用型

保留 **description** 字段的技能，代理能够看到并自主触发；人类仍可输入其名称，因此模型调用*始终包含*用户可达性。不存在仅模型可用的状态：description 只会增加代理发现能力，从不移除人类访问能力。它以每轮永久承担**上下文负载**为代价，换取可发现性。其他技能也能调用它，因为使代理能够发现的 description 同时让它可被调用。内容全是**参考资料**的模型调用型技能，也可以作为共享参考资料的归属地：其他技能能够调用它，因此多个技能都需要的资料可放在一处。只有代理必须自行抵达某技能时才选择模型调用；如果它只会被手工调用，就去掉 description，不再承担上下文负载。

_避免使用_：能力、工具、功能

### 用户调用型

从代理可见范围中移除 **description** 的技能，对代理不可见，只有人类输入名称才能调用；它是用户*独占*，而**模型调用型**是用户*与代理均可用*。它用放弃代理可发现性换取零**上下文负载**。因为没有 description，除人类外无人能抵达它，其他技能也不能触发它。

_避免使用_：过程、工作流、命令

### Description

技能的机器可读触发器，也是**模型调用型**技能被迫始终加载的唯一**上下文指针**。它是否存在，本身就决定调用轴：保留它，技能就是模型调用型（也可被其他技能调用）；删除它，技能就是**用户调用型**，只有人类可达。它是模型调用型技能**上下文负载**的来源。

_避免使用_：frontmatter、摘要

### 上下文指针

代理上下文中持有的一项引用，用于命名上下文外的材料，并编码抵达该材料的条件。**description** 是顶层上下文指针（上下文窗口 → 技能）；指向披露文件的指针是下一层的同类对象。决定代理*何时*以及以多高*可靠性*抵达材料的是措辞，而非目标。必须使用的目标藏在措辞薄弱的指针后面，会造成方差 bug：先修正措辞，只有收紧后仍失败时，才将材料内联。

_避免使用_：链接、引用、导入

### 上下文负载

**模型调用型**技能施加于代理上下文窗口的成本：其 **description** 始终加载，不断消耗 token 和注意力。**用户调用型**技能能够避开它；它也是拆出更多模型调用型技能时的制动器。

_避免使用_：token 成本、上下文膨胀

### 认知负载

**用户调用型**技能施加于人类的成本，即人类必须记住哪些技能存在以及何时使用，每个人类都是索引。**模型调用**通过代理可发现性消除它；它也是拆出更多用户调用型技能时的制动器。这不是需要最小化的成本，而是人类能动性的代价，也是某些技能保持用户调用型的原因。把它用于需要人类判断的位置，在不需要的位置消除它。

_避免使用_：人类索引、负担、开销

### 路由技能

一种**用户调用型**技能，负责指向其他用户调用型技能，逐一命名并说明何时使用，让人类只需记住一个技能，而不是许多个。它只能提示，不能触发：用户调用型技能没有 **description**，除人类外无人能抵达。它用于在用户调用型技能增多时消除**认知负载**。

_避免使用_：分发器、菜单、注册表、索引、路由过程

### 粒度

技能被划分得多细。更细的划分会增加两种负载之一：更多**模型调用型**技能增加**上下文负载**，因为更多 description 挤占窗口并争夺注意力；更多**用户调用型**技能增加**认知负载**，因为人类要记住并调用更多技能。两种切法指导划分。按**调用机制**切分：当存在一个独特的**引导词**，即你确实会在提示词中使用的触发词时，拆出模型调用型技能。按**顺序**切分：当某一步的**完成后步骤**需要隐藏时，拆分步骤序列，因为把当前步骤隔离到独立上下文会清除后续内容。也要警惕反方向：合并序列会让每一步的完成后步骤暴露给当前步骤，诱发过早完成。

_避免使用_：分块、模块化

## 信息层级

技能内容的组织方式，以及每项内容位于阶梯的哪一层。

### 信息层级

按照代理需要内容的即时程度为技能内容排序。它是一座由两次切分产生的单一阶梯：内容位于文件内还是指针之后，以及它属于步骤还是参考资料。层级如下：

- **步骤**：位于文件内，首要层级
- **参考资料**：位于文件内，次要层级
- **参考资料**：已披露，位于**上下文指针**之后

没有**步骤**的技能只使用下面两层，通常是一组合理的扁平同级内容（例如一次审查的所有规则都在同一层）；这完全没有问题，不是坏味道。信息层级与调用机制相互独立：无论内容全是步骤、全是参考资料或两者兼有，技能都可以是模型调用型或用户调用型。当技能包含步骤时，本应披露却仍留在文件内的参考资料会掩埋步骤，使代理是否注意到它们变成抛硬币；这是方差杠杆，而不只是可读性问题。让阶梯顶层保持清晰，把一切可以下移的内容向下推。

_避免使用_：结构、组织、布局

### 步骤

代理按顺序执行的动作。当技能包含步骤时，它们是内容的首要层级，也是值得留在 SKILL.md 中的部分。并非每个技能都有步骤：技能可以全是步骤（`tdd`）、全是**参考资料**（一次审查），或两者兼有，与调用机制无关。每个步骤都以一个**完成判据**结束，无论该判据清晰还是含糊。

_避免使用_：工作流、指令、编排

### 参考资料

代理按需查阅的材料，例如定义、事实、参数、示例和条件性说明。当技能含有**步骤**时，它次于步骤；当技能没有步骤时，它就是全部内容；它也可以完全位于技能之外，参见**外部参考资料**。通过**上下文指针**抵达，是**渐进披露**的首要候选。

_避免使用_：辅助材料、文档、背景

### 外部参考资料

位于技能系统之外的**参考资料**：一个普通文件，没有 **description**，没有**步骤**，不能被调用，但任何技能都可以指向。它适合承载无需自行触发的共享参考资料，也是两个**用户调用型**技能唯一可用的共享归属地，因为二者都没有 description，无法相互触发。

_避免使用_：文档、资源、知识库

### 渐进披露

让**参考资料**沿阶梯下移，从 SKILL.md 移到**上下文指针**之后，使顶层保持清晰。它主要不是 token 优化，而是保护**信息层级**的方式。是否披露由**分支**决定：只有部分分支需要的内容应被披露，每条路径都需要的内容保持内联。如果必须使用的材料对应的指针触发不可靠，先收紧措辞，只有这样仍失败时才拉回内联。

_避免使用_：延迟加载、分块

### 共置

把代理需要同时使用的材料放在同一处，例如将一个概念的定义、规则和注意事项置于同一标题下，而非散落在文件中，使读取一部分时也能看到相邻内容。它是**信息层级**在文件内部的配套概念：信息层级决定一项内容位于*多深*的位置；共置决定它到达该位置后与*什么相邻*。参考资料正文没有通用格式；判断标准是技能应当像为代理编写的文档，而归组后的材料比散落材料更符合这一点。它不同于**重复**：重复是在两处给出同一含义，散落则是把同一个含义切碎到多个位置。

_避免使用_：分组、聚类、内聚

### 蔓延

*失败模式。* 技能单纯过长，即 SKILL.md 行数太多，与内容是否陈旧或重复无关。即使每一行都仍有效且独一无二，技能仍可能蔓延。它损害可读性（代理必须跋涉更久才能行动，注意力被过量内容稀释）、可维护性（每多一行就多一项需要维持**相关性**的内容）并浪费 token。修复方式是使用**信息层级**：把**参考资料**推到**上下文指针**之后，并按**分支**或顺序拆分，让每条路径只携带所需内容。它不同于**沉积**（陈旧累积造成的长度）和**重复**（相同含义造成的长度）；蔓延就是长度本身，无论成因为何。

_避免使用_：膨胀、长度、大小、冗长

## 引导

把代理运行时行为塑造为更具**可预测性**的杠杆。

### 分支

技能的一种独特调用方式，即技能处理的一种情形，使不同运行会经过不同路径。包含许多步骤的技能可能有许多分支；线性技能则没有。

_避免使用_：路径、情形、分叉

### 引导词

一个已经存在于模型预训练中的紧凑概念，也称 _Leitwort_，代理在运行技能时用它思考。它通过调用模型已有先验，以最少 token 编码行为原则，例如 _lesson_、_proximal zone of development_、_fog of war_、_tracer bullets_。以 token 而非整句的形式重复，它会积累分布式定义，并锚定整片行为区域。也可以自行创造新词，但前提是给出清晰定义；虚构词无法调用先验，你必须用定义 token 支付预训练词免费提供的内容。优先寻找已有词汇。

引导词从两个方向服务**可预测性**。正文中，它锚定**执行**：每次出现这个概念时，代理都会采取同类行为；在扁平参考资料中，它会把注意力聚焦到一类目标上，调用每次运行所需的检查。**description** 中，它锚定**调用**，而且不只在技能内部：同一个词出现在提示词、文档和代码库中时，代理会把共享语言与技能相连，从而更可靠地触发。用你确实会在需要该技能时使用的引导词来编写 description。

_避免使用_：关键词、术语、母题

### 完成判据

告诉代理一项工作已经完成的条件，即它用来判断的目标。两项属性让它成为杠杆，而非普通品质。**清晰度**（代理能否分清完成与未完成？）抵抗**过早完成**：含糊边界（“已经理解”）让代理可以宣布完成并滑向下一步；这个轴需要存在*步骤*才会生效，因为过早完成发生在步骤之间。**要求强度**（它要求做多少？）决定**幕后执行**：“覆盖每个被修改的模型”会迫使代理做出彻底工作，而“产出变更清单”不会。这个轴*不*依赖步骤：它也能约束一组扁平参考资料，让没有步骤的技能仍然携带穷尽标准（“应用每一条规则”）。最强判据既可检查，又穷尽。

_避免使用_：完成条件、退出条件、停止规则

### 幕后执行

代理在单个步骤内部完成的幕后工作：读取文件、探索代码库、进行修改，并自行挖掘所需内容，而不是转嫁给用户。它位于步骤结构下方，从不作为独立步骤写出，而是潜藏在措辞中，由代理而非技能控制。它与**完成后步骤**跨步骤产生的拉力相对，是步骤内部的作用。强有力的**引导词**（_comprehensive_、_thorough_）或要求穷尽工作的**完成判据**会提高幕后执行，包括把要求强度施加于扁平参考资料，从而推动纯参考技能覆盖所有层级。缺少这种要求，或**过早完成**截断步骤时，幕后执行都会变薄。

_避免使用_：范围、投入、勤勉、覆盖率

### 完成后步骤

当前**步骤**之后的其他步骤。它们一旦可见，就会把代理向前拉入**过早完成**；看得越多，拉力越强。防御方式是拆分步骤序列，把后续步骤隐藏起来。

_避免使用_：地平线、战争迷雾、前瞻

### 过早完成

*失败模式。* 当前步骤尚未真正完成便结束，因为代理的注意力从工作本身滑向了“完成”。它是发生在步骤之间的失败，需要存在**步骤**；没有步骤的技能提前退出，不属于过早完成，而是未满足要求下的薄弱**幕后执行**。它是两股力量的拉锯：可见的**完成后步骤**产生前拉，**完成判据**的清晰度产生阻力；锋利、可检查的边界能固定当前步骤，含糊边界则会退让。模糊是必要条件：无论后续步骤有多少，清晰边界都能抵抗拉力，因此从不仓促的步骤无需防御。两种杠杆可以稳住步骤，但使用顺序明确：**先收紧边界**，因为它局部且便宜。只有当判据无法进一步明确且确实观察到仓促行为时，才**隐藏后续步骤**。隐藏只在真实上下文边界上有效（用户调用型交接或子代理派发）；内联的模型调用不会清除后续步骤。它是幕后执行变薄的一个原因，但二者并不相同：即使步骤运行到完整结束，幕后执行仍可能薄弱。

_避免使用_：过早关闭、赶进度、仓促、走捷径

### 否定式引导

*失败模式。* 通过禁止来引导，即告诉代理*不要*做什么，会把被禁止的行为拖入上下文，反而提高其可用性。_Don't think of an elephant_ 之后，语境中只剩大象；_never write verbose comments_ 刚刚激活的正是冗长模式。否定词只是弱修饰，无法压过被强烈激活的概念，因此禁令读起来一半像是在要求执行。它的**引导词**就是那头*大象*：禁令把什么带入框架，什么就成为引导词。修复方式是提示**正向目标**，例如描述“编写单行注释”，使被禁止的行为从未被提及。只有无法用正面方式表述的硬性护栏才值得保留禁令；即便如此，也要同时给出正向目标，让注意力落在应该做什么上。

_避免使用_：讽刺性反弹、不要式提示、粉红大象

## 精简

保持技能简洁，每种补救方式都与它修复的失败模式配对。

### 唯一事实来源

每个含义只存在于一个权威位置的理想状态，使技能行为的一项变化只需在一处编辑。**重复**违背这一状态。

_避免使用_：归属地、规范位置

### 重复

*失败模式。* 同一含义拥有多个**唯一事实来源**。它增加维护成本（改一处，就必须同步其他位置）、token 成本，并夸大显著性：重复一个含义会把它在阶梯上的权重抬到超过实际层级。它是**引导词**的意外反面；引导词有意通过重复一个 token 提高注意力，从不重复整个含义。

_避免使用_：复述、冗余

### 相关性

一行内容是否仍与技能所做的事有关，是决定保留什么的视角。内容会通过两种方式失去相关性：从未真正影响任务（仅是阐述，或本应披露的**分支**），或随着其描述的行为与世界变化而过时。较短的技能更容易保持相关，因为检查每一行的成本更低。它不同于**无效指令**：相关性询问一行是否与任务有关，而不是它是否改变行为。

_避免使用_：承重、陈旧度、新鲜度

### 沉积

*失败模式。* 旧内容层层沉淀在技能中，从未清除，因为添加让人安心，而删除令人担忧；陈旧且无关的行不断堆积，必须像钻取岩芯一样穿透它们，才能找到仍有效的内容。没有精简纪律的技能默认都会走向这里。它是**相关性**的缓慢侵蚀，不同于**重复**造成的同义复现。

_避免使用_：增生、膨胀、垃圾、腐化

### 无效指令

*失败模式。* 因模型默认已经会执行而没有改变任何行为的指令；你付出负载，却只是告诉代理做它本来就会做的事。测试方式是：与默认行为相比，这一行是否改变了行为？一行可以完全**相关**，但仍然无效。让**引导词**低成本生效的同一套先验，也让无效指令毫无价值。

引导词是一种*技巧*；无效指令是对一行内容的*判决*，二者会交叉。弱到无法超越默认行为的引导词属于无效指令（代理本来就还算仔细时写 _be thorough_）；修复方式是换成能通过判决的更强词（_relentless_），而不是换一种技巧。因此，无效指令测试“与默认相比是否改变行为？”也用于评判引导词是否值得重复。它取决于模型，而不是读者：两个人对某一行是否无效产生分歧，本质上是在争论默认行为，应通过实际运行技能解决，而非辩论。

_避免使用_：冗余指令、重述显而易见之事、反复啰嗦

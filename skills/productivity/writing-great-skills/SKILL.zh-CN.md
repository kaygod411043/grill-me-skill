技能的存在，是为了从随机系统中约束出确定性。**可预测性**是根本品质：代理每次都采用相同的*过程*，而不是产生相同的输出。下文中的每个杠杆都服务于它。

**粗体术语**在 [`GLOSSARY.zh-CN.md`](GLOSSARY.zh-CN.md) 中定义，需要完整含义时查阅该文件。

## 调用机制

有两种选择，各自承担不同成本：

- **模型调用型**技能保留 **description**，使代理可以自主触发它，其他技能也能调用它；你仍然可以输入其名称。它会增加**上下文负载**，因为 description 在每一轮都位于上下文窗口中。机制：省略 `disable-model-invocation`，并编写面向模型、含丰富触发条件的 description（"Use when the user wants…, mentions…"）。
- **用户调用型**技能不让代理看到 description：只有你输入其名称才能调用，其他技能也无法调用。上下文负载为零，但会产生**认知负载**：*你*就是索引，必须记住它的存在。机制：设置 `disable-model-invocation: true`；`description` 改为面向人类的一行摘要，去掉触发条件列表。

只有当代理必须自行调用该技能，或另一个技能必须调用它时，才选择模型调用。如果它只会被手工调用，就设为用户调用型，不承担上下文负载。

当用户调用型技能多到难以记住时，用**路由技能**消除累积的认知负载：一个用户调用型技能，负责列出其他技能并说明何时使用。

## 编写 description

模型调用型 **description** 承担两项工作：说明技能是什么，并列出应触发它的**分支**。每个词都会增加**上下文负载**，因此 description 比正文更值得严格精简：

- **把技能的引导词放在最前面**：description 正是在这里完成调用工作。
- **每个分支只保留一个触发条件。** 只是换个说法来重复同一分支的同义词属于**重复**；“使用 TDD 构建功能……要求测试优先开发”只是把一个分支写了两遍。合并它们，只保留真正不同的分支。
- **删掉正文已有的身份说明。** description 只保留触发条件，以及必要的“当另一个技能需要……”调用条款。

## 信息层级

技能由两类内容构成：**步骤**和**参考资料**。二者可以自由组合：技能可以全是步骤、全是参考资料，或两者兼有。核心决策是使用哪一类，以及让每项内容位于**信息层级**的哪一层。这个阶梯按代理需要材料的即时程度排序：

1. **技能内步骤**：`SKILL.md` 中按顺序执行的动作，是首要层级。每个步骤以**完成判据**结束，用它判断工作已经完成。判据应当*可检查*（代理能否分清完成与未完成？），并在必要时*穷尽*（“覆盖每个被修改的模型”，而非“产出变更清单”）；含糊的判据会诱发**过早完成**。
2. **技能内参考资料**：`SKILL.md` 中按需查阅的定义、规则或事实。它们常常是一组合理的扁平同级内容（例如一次审查的每条规则位于同一层），这不是坏味道。*本技能全部由参考资料组成。*
3. **外部参考资料**：从 `SKILL.md` 下移到独立文件，并通过**上下文指针**访问；只有指针触发时才加载。（范围从*已披露*参考资料，即仍属于技能的同级文件如 `GLOSSARY.md`，一直延伸到完全位于技能系统之外、任何技能都可指向的**外部参考资料**。）

高要求的完成判据会推动扎实的**幕后执行**，无论技能是否包含步骤；因为“应用每一条规则”对扁平参考资料的约束，与“完成每一步”对步骤序列的约束相同。

下移得太少，顶层就会臃肿；下移得太多，又会隐藏代理真正需要的材料。整个决策的关键就是这种张力。

**渐进披露**是沿阶梯下移的动作：把内容从 `SKILL.md` 移入链接文件，使顶层保持清晰。机制：在技能目录中放置一个按内容命名并被链接的 `.md` 文件；本技能将完整定义披露到 `GLOSSARY.md`。有些技能有多种使用方式，每种不同方式都是一个**分支**，即不同运行会走不同路径。分支是最清晰的披露测试：每个分支都需要的内容保持内联，只有部分分支需要的内容放到指针后面。决定**上下文指针**何时、以多高可靠性触发的，是其*措辞*而非目标。

如果说阶梯决定内容放在*多深*的位置，**共置**则决定它在那里与*什么相邻*：把同一概念的定义、规则和注意事项放在同一个标题下，而非散落在文件中，这样读取一部分时也会看到相邻内容。

## 何时拆分

**粒度**表示技能划分得多细。每次拆分都会增加两种负载之一，因此只有收益足够时才拆分。两种切法：

- **按调用拆分**：当存在一个应独立触发的**引导词**，或另一个技能必须调用它时，拆出**模型调用型**技能。新的常驻 **description** 会产生**上下文负载**，因此独立可达性必须值得这项成本。
- **按顺序拆分**：当后续仍可见的**步骤**（当前步骤的**完成后步骤**）诱使代理仓促结束眼前步骤（**过早完成**）时，拆分步骤序列。把后续步骤移出视野，能鼓励代理在当前任务上做更多**幕后执行**。

## 精简

让每个含义只有一个**唯一事实来源**，即一个权威位置，使行为变更只需编辑一处。

逐行检查**相关性**：它是否仍与技能所做的事有关？

然后逐句而非仅逐行寻找**无效指令**：单独对每个句子运行无效指令测试；一旦失败，就删掉整个句子，而不是只修剪几个词。保持激进，大多数失败的文字都应删除，而非重写。

## 引导词

**引导词**是模型预训练中已经存在、代理在运行技能时用来思考的紧凑概念（例如 _lesson_、_fog of war_、_tracer bullets_）。它在文本中反复出现（但未必必须重复，强有力的引导词可能只需一次），以分布式方式积累定义，并通过调用模型已有先验，用最少 token 锚定整片行为区域。

它从两个方向服务可预测性。正文中，它锚定*执行*：每次看到这个词，代理都会采取相同类型的行为。description 中，它锚定*调用*：当同一个词出现在提示词、文档和代码中时，代理会把共享语言与技能相连，从而更可靠地触发。

寻找用引导词重构技能的机会。一个在三处展开的三元组（**重复**）、description 中花一整句暗示的概念，都在请求被**折叠**成一个 token。例如：

- "fast, deterministic, low-overhead" -> _tight_：把一个阶段中重复说明的品质折叠为一个预训练词（一个 _tight_ loop）。
- "a loop you believe in" -> _red_：把模糊门槛转化为二元可观察状态（循环要么在该 bug 上变 _red_，要么没有）。

这样会获得双重收益：token 更少，并且为代理提供更锋利的思考挂钩。假设每个技能都携带着可由引导词淘汰的重述，去找到它们。

## 失败模式

用这些模式诊断用户在技能使用中可能遇到的问题。

- **过早完成**：步骤尚未真正完成就结束，注意力滑向了“完成”本身。防御顺序：先收紧完成判据（便宜、局部）；只有当判据无法进一步明确且确实观察到仓促行为时，才通过拆分隐藏完成后步骤（按顺序切分）。
- **重复**：同一含义出现在多个位置。它增加维护与 token 成本，还会把该含义在阶梯上的显著性抬到超过实际等级。
- **沉积**：因为添加让人安心、删除令人担忧而逐渐沉淀的陈旧层。没有精简纪律的技能默认都会走向这里。
- **蔓延**：技能单纯过长，即使每一行都仍有效且独一无二。它损害可读性、可维护性并浪费 token。修复方式是使用阶梯：把**参考资料**披露到指针之后，并按**分支**或顺序拆分，让每条路径只携带所需内容。
- **无效指令**：模型默认已经会遵守的句子，付出负载却什么都没有改变。测试方式：与默认行为相比，它是否改变了行为？弱引导词（代理本来就还算仔细时写 _be thorough_）属于无效指令；修复方式是使用更强的词（_relentless_），而不是换一种技巧。
- **否定式引导**：用禁令引导会适得其反。_don't think of an elephant_ 把大象带入语境，使其更容易出现，而不是更少。改为提示**正向目标**：直接描述目标行为，使被禁止的行为根本不被提起。只有在无法用正面方式表达的硬性护栏中才保留禁令，并且即便如此，也要同时说明应该做什么。

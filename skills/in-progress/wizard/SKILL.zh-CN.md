# 向导

**向导**是一段 bash 脚本，逐步引导用户完成手工流程。这类流程既繁琐到不适合手动执行，也繁琐到不值得每次都重新向 AI 解释。向导会打开每个 URL，准确说明要点击和复制什么，采集值并写到正确位置（`.env`、GitHub secret），在每个阶段进行确认，并显示剩余进度。它可以配置第三方服务、执行一次性迁移，或把项目从一种状态迁移到另一种状态。

[template.sh](template.sh) 已经解决了良好 UX：带剩余时间的进度、确认门、跨平台 URL 打开（包括 WSL）、隐藏的 secret 输入、幂等的 `.env` 更新、`gh secret`/`gh variable` 写入，以及结束摘要。**你的工作只包括界定流程范围并编写各个阶段。** 每个向导中 `STAGES` 标记上方的库都完全相同，这种一致性正是关键；绝不能手工编辑它。

向导默认是临时工件：为单次运行而构建，保存在 scratch 或 `scripts/` 路径，任务完成后删除。只有当用户希望在仓库中保留一条可重复使用的配置路径时，才提交它。

## 流程

### 1. 界定流程范围

找出用户必须执行的每一个手工步骤，以及过程中要采集的每一个值。先阅读仓库，不要毫无背景地提问：

- 对于配置：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`；每个 `secrets.*` / `vars.*` 引用都是向导必须生成的值。
- 对于迁移或转换：确认当前状态、目标状态，以及二者之间不可逆的操作。

然后向用户展示按顺序排列的阶段清单及每个阶段产生的值，并请求确认；用户可以添加、删除或重新排序。

**完成判据：** 每个阶段都已按顺序命名；对于每个采集值，都知道：(a) 用户从哪里获得它；(b) 它写到哪里（`.env`、GitHub secret、两者兼有或都不写，有些阶段只有操作）；(c) 它是 secret（隐藏输入）还是公开值。

### 2. 绘制每个阶段的旅程

为每个阶段写出用户要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、它填充哪个变量。例如："Dashboard → Developers → API keys → Reveal test key → copy"。如果确实不知道当前 UI 或准确命令，明确说明并询问用户或查阅文档；绝不能虚构可能不存在的步骤。

**完成判据：** 每个阶段都能追溯到陌生人也能照做的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每一步对应的一个 `stage` 替换示例阶段，并按依赖顺序排列。使用库 helper：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`，并为 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置诚实的估算值，用于驱动剩余时间显示。

达到模板设定的标准：先打开 URL，再索取其中的值；对所有 secret 使用 `ask_secret`；通过 `write_env` 写入每个需要持久化的值；只有 CI 确实需要的值才使用 `set_secret`；任何不可逆操作前都使用 `confirm`。每个 `stage` 都会清屏，只显示当前步骤，因此每个阶段只处理一项聚焦任务，避免用户需要的信息滚出屏幕。不要触碰标记上方的库。

### 4. 验证并交接

- 运行 `bash -n <script>`；如果有 `shellcheck`，也运行它。
- 运行 `chmod +x <script>`。
- 不要自行端到端运行；它会打开浏览器并阻塞等待用户输入。改为静态追踪：步骤 1 中的每个值都已采集并落到约定位置，而且每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全一致。
- 告诉用户如何运行。如果这是可重复使用的配置路径，提交它并从 README 链接过去，让下一个人直接运行脚本，而不是再次询问 AI。

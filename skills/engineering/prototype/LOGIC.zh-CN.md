# 逻辑原型

一个微型交互式终端应用，让用户手动驱动状态模型。当问题涉及**业务逻辑、状态转换或数据形态**时使用，即那些纸面上看似合理，但只有经过真实场景推动后才会感觉不对的问题。

## 何时适合这种形态

- “我不确定这个状态机能否处理先发生 X、再发生 Y 的边界情况。”
- “这个数据模型真的能表达……这种情况吗？”
- “我想在正式编写前感受一下 API 应该是什么样子。”
- 任何用户想要**按下按键并观察状态变化**的情况。

如果问题是“它应该长什么样”，则选错了分支。使用 [UI.zh-CN.md](UI.zh-CN.md)。

## 流程

### 1. 陈述问题

在编写代码之前，写明正在为哪个状态模型创建原型，以及要回答什么问题。用一个段落写在原型 README 或文件顶部注释中。回答错误问题的逻辑原型纯属浪费；明确问题，使它以后仍可被核对，无论用户现在正在旁观，还是离线后回来查看。

### 2. 选择语言

使用宿主项目采用的语言。如果项目没有明显的运行时（例如文档仓库），则询问用户。

遵循项目现有的工具约定，不要只为原型引入新的包管理器或运行时。

### 3. 在可移植模块中隔离逻辑

把真正回答问题的逻辑放在一个小型、纯粹的接口之后，以便之后把它提取出来，直接放进真实代码库。外围 TUI 是一次性的，但逻辑模块不应该是。

正确形态取决于问题：

- **纯 reducer**：`(state, action) => state`。适合 action 是离散事件、state 是单一值的情况。
- **状态机**：显式定义状态和转换。适合“当前究竟允许哪些 action”本身就是问题一部分的情况。
- **作用于普通数据类型的一小组纯函数**。适合不存在隐式当前状态，只有转换的情况。
- **方法表面清晰的类或模块**。适合逻辑确实拥有持续内部状态的情况。

选择最符合当前问题的形态，而不是最容易连接 TUI 的形态。保持纯粹：不做 I/O，不包含终端代码，不使用 `console.log` 控制流程。TUI 导入并调用它，依赖方向不能反过来。

这正是原型在生命周期结束后仍有用的原因：问题得到回答后，可以把经过验证的 reducer、machine 或函数集单独提取到真实模块中。

### 4. 构建能暴露状态的最小 TUI

把它构建为**轻量 TUI**：每个 tick 都清屏（`console.clear()` / `print("\033[2J\033[H")` / 等价方式），并重新渲染整个画面。用户应始终看到一个稳定视图，而不是不断增长的回滚内容。

每个画面按以下顺序包含两部分：

1. **当前状态**：使用易读、便于 diff 的格式（每行一个字段，或格式化 JSON）。字段名或章节标题使用**粗体**，不太重要的上下文（时间戳、ID、派生值）使用**暗色**。可以直接使用原生 ANSI 转义码：`\x1b[1m` 粗体、`\x1b[2m` 暗色、`\x1b[0m` 重置。除非项目已经有样式库，否则无需为此引入。
2. **键盘快捷键**：列在底部，例如 `[a] add user  [d] delete user  [t] tick clock  [q] quit`。可以将按键加粗、说明变暗，也可以反过来，只要清晰易读。

行为：

1. **初始化状态**：使用单个内存对象/struct。启动时渲染第一帧。
2. 每次**读取一个按键（或一行）**，并分派给修改状态的处理器。
3. 每次操作后**重新渲染**整个画面，不要追加，要替换。
4. **循环直至退出。**

整个画面应能放进一屏。

### 5. 用一条命令运行

向项目已有的任务运行器（`package.json` scripts、`Makefile`、`justfile`、`pyproject.toml`）添加脚本。用户应运行 `pnpm run <prototype-name>` 或等价命令，而无需记住路径。

如果宿主项目没有任务运行器，只需把命令放在原型 README 顶部。

### 6. 交给用户

向用户提供运行命令。他们会亲自驱动原型；最有价值的时刻是他们说“等等，这不应该发生”或“原来如此，我以为 X 会不同”。这些是*想法*中的缺陷，而发现它们正是原型的意义。如果用户想添加新 action，就添加。原型会不断演化。

### 7. 留存答案和原型

原型回答问题后，先留存答案，再按照 [SKILL](SKILL.zh-CN.md) 所述方式留存原型。逻辑分支的具体映射为：经过验证的 reducer、machine 或函数集被提取到真实模块中（决策被吸收）；TUI 外壳则随原型一同保存在把它作为第一手资料的一次性分支中。

## 反模式

- **不要添加测试。** 需要测试的原型已经不再是原型。
- **不要连接真实数据库。** 除非问题专门与持久化有关，否则使用内存存储。
- **不要泛化。** 不要考虑“如果将来要支持 X 怎么办”。原型只回答一个问题。
- **不要把逻辑和 TUI 混在一起。** 如果 reducer 或状态机引用 `console.log`、prompt 或终端转义码，它就不再可移植。TUI 应是纯模块之上的薄壳。
- **不要把 TUI 外壳发布到生产环境。** 外壳针对终端中的手动驱动进行了优化。其背后的逻辑模块才是值得保留的部分。
